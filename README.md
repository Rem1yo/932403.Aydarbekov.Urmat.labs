# Лабораторная работа 8. Итоговый мини-проект

Цель: применить все изученные технологии в рамках одного проекта.

Вариант 2: «Каталог товаров интернет-магазина» (товары и категории).

Проект собран на базе лабораторных 1-7: сайт «Путешественник», сервер на Express, SQLite. К нему добавлен каталог товаров с фильтрами, поиском, пагинацией и полным CRUD. Каталог открывается по адресу `/shop`, ссылка на него есть в меню сайта.

## Как запустить

```bash
npm install
npm start
```

Сайт откроется на http://localhost:3000, каталог на http://localhost:3000/shop. Тесты:

```bash
npm test
```

При первом запуске создаётся файл `catalog.db` с таблицами и 15 тестовыми товарами. Он отдельный от `shop.db` из лабораторной 7, потому что таблицы в нём устроены иначе. Файлы баз в репозиторий не попадают.

## Схема базы данных

```
+---------------------+          +-----------------------------+
| categories          |          | products                    |
+---------------------+          +-----------------------------+
| id    INTEGER PK    |<---------| id           INTEGER PK     |
| name  TEXT UNIQUE   |   1 : N  | category_id  INTEGER FK     |
+---------------------+          | name         TEXT NOT NULL  |
                                 | price        REAL >= 0      |
                                 | stock        INTEGER >= 0   |
                                 | description  TEXT           |
                                 +-----------------------------+
```

Одна категория содержит много товаров, у каждого товара ровно одна категория. Связь `products.category_id -> categories.id` защищена внешним ключом, а на `price` и `stock` стоят ограничения `CHECK (... >= 0)`, поэтому даже при ошибке в коде отрицательное значение в базу не попадёт. На `category_id` создан индекс.

Запросы с `JOIN` (`products.js`, `categories.js`) снабжены комментариями, зачем они нужны.

## API

Все ответы в формате JSON. Ошибки приходят в виде `{ "error": "понятный текст" }`.

| Метод и адрес | Что делает |
|---|---|
| `GET /api/categories` | категории с количеством товаров в каждой |
| `GET /api/products` | список товаров с фильтрами и пагинацией |
| `GET /api/products/:id` | один товар |
| `POST /api/products` | добавить товар (ответ 201) |
| `PUT /api/products/:id` | изменить товар целиком |
| `DELETE /api/products/:id` | удалить товар |

### Параметры `GET /api/products`

| Параметр | Значение | По умолчанию |
|---|---|---|
| `category` | id категории | все |
| `minPrice`, `maxPrice` | границы цены, включительно | без границ |
| `search` | часть названия, регистр не важен (в том числе для русских букв) | без поиска |
| `page` | номер страницы, от 1 до 1000000 | 1 |
| `limit` | товаров на странице, от 1 до 50 | 6 |

Ответ: `{ items: [...], total, page, limit, totalPages }`. Каждый товар: `{ id, name, price, stock, description, categoryId, categoryName }`.

### Тело `POST` и `PUT`

```json
{ "name": "Фонарь", "price": 990.5, "stock": 7, "categoryId": 3, "description": "Необязательное описание" }
```

### Правила проверки

| Поле | Правило |
|---|---|
| `name` | непустое, не длиннее 100 символов, пробелы по краям обрезаются |
| `price` | число от 0 до 1 000 000 000, не больше двух знаков после запятой |
| `stock` | целое число от 0 до 1 000 000 |
| `categoryId` | id существующей категории |
| `description` | текст не длиннее 1000 символов, можно не указывать |

### Коды ошибок

| Код | Когда |
|---|---|
| 400 | неверные данные или параметры, битый JSON |
| 404 | товара нет, id не состоит из одних цифр, неизвестный адрес `/api/...` |
| 413 | слишком большое тело запроса |
| 500 | непредвиденная ошибка сервера |

### Примеры запросов

```bash
curl "localhost:3000/api/products?category=3&minPrice=500&maxPrice=2000&page=1"

curl "localhost:3000/api/products?search=%D1%80%D1%8E%D0%BA%D0%B7%D0%B0%D0%BA"

curl -X POST localhost:3000/api/products \
  -H "Content-Type: application/json" \
  -d '{"name":"Фонарь","price":990.5,"stock":7,"categoryId":3}'

curl -X PUT localhost:3000/api/products/1 \
  -H "Content-Type: application/json" \
  -d '{"name":"Рюкзак 60 л","price":3600,"stock":10,"categoryId":1,"description":"Обновлённое описание"}'

curl -X DELETE localhost:3000/api/products/1
```

## Что умеет страница каталога

- карточки товаров: название, категория, цена, остаток на складе (или «Нет в наличии»)
- боковая панель фильтров: поиск, категория, диапазон цен; на телефоне панель стоит над списком
- пагинация по 6 товаров; после удаления последнего товара на последней странице каталог сам переходит на предыдущую
- кнопка «В корзину» (имитация): количество в корзине не больше остатка, число в шапке хранится в `localStorage`
- модальное окно с подробностями товара и модальная форма добавления и редактирования (элемент `dialog`)
- удаление с подтверждением прямо в карточке, без `window.confirm`
- понятные сообщения об ошибках для 400, 404, 500 и для случая «нет связи с сервером»
- тёмная тема подхватывается из настройки главной страницы

## Качество кода

- **Разделение логики.** Сервер разбит на слои: маршруты принимают запрос и отвечают, `validation.js` проверяет данные, `products.js` и `categories.js` общаются с базой. На странице функции разделены по задачам: запросы (`apiRequest`), отрисовка (`renderProducts`), фильтры, форма, корзина.
- **Без «магических» значений.** Пределы и тексты вынесены в константы (`NAME_MAX_LENGTH`, `MAX_PRICE`, `PAGE_SIZE` и другие). Пределы на странице совпадают с серверными, об этом написан комментарий.
- **Защита от XSS.** На странице нигде не используется `innerHTML`: текст товаров вставляется только через `textContent`. Проверено на названии `<img src=x onerror=alert(1)>`.
- **Защита от SQL-инъекций.** Все значения передаются в запросы параметрами (`?`), а не склеиваются со строкой. Спецсимволы `%` и `_` в поиске экранируются.
- **Проверка на клиенте и на сервере.** Форма проверяет данные до отправки, сервер проверяет заново, потому что запрос можно отправить и без страницы. Отрицательные цены и остатки отклоняются на трёх уровнях: форма, сервер, ограничения `CHECK` в базе.
- **Доступность.** Семантические теги (`header`, `nav`, `main`, `aside`, `section`), подписи `label` у всех полей, `aria-label` у кнопок (начинается с видимого текста и содержит название товара), `aria-current` у текущей страницы, `aria-busy` у списка, живая область (`aria-live`) для сообщений, `dialog` с `aria-labelledby`. После перерисовки списка фокус клавиатуры возвращается на нужную кнопку.
- **Адаптивность.** Стили для телефона написаны первыми, для широких экранов добавлены от 768px. Сетка карточек подстраивается под ширину, длинные слова переносятся.
- **Контраст.** Все цвета текста не ниже 4.5:1 в обеих темах.

## Ревью кода

Код проверил отдельный рецензент без доступа к моим заметкам. Каждое замечание я проверял сам: часть воспроизвёл командами и исправил, часть отклонил.

**Подтверждено и исправлено:**

| Что нашли | Как проявлялось | Что сделано |
|---|---|---|
| нет верхней границы цены и остатка, не проверяются копейки | цена `1e308` и остаток `1e21` принимались, цена `10.999` сохранялась | границы 1 000 000 000 и 1 000 000, не больше двух знаков после запятой; тесты |
| огромный номер страницы | `?page=1e21` давал ошибку сервера 500 | страница не больше 1 000 000, тест |
| нестрогий разбор id | `/api/products/0x10` открывал товар 16, `/api/products/1e2` искал товар 100 | id должен состоять только из цифр, тест |
| слишком большое тело запроса | ответ 500 вместо 413 | отдельная обработка, тест |
| устаревший ответ перезаписывает свежий | при быстрых нажатиях на экране оставались результаты прошлого запроса | счётчик запросов, проверка в браузере с искусственной задержкой |
| потеря фокуса клавиатуры после перерисовки | после «В корзину» Tab начинался с начала страницы | фокус возвращается на нужную кнопку или заголовок каталога |
| двойной клик по «Да, удалить» | второй запрос давал ложное «Товар не найден» | повторное нажатие игнорируется |
| длинное слово в названии | 100 символов подряд вылезали за карточку и давали горизонтальную прокрутку | `overflow-wrap`, `minmax(0, 1fr)` |
| корзина хранит больше остатка | после уменьшения остатка в корзине оставалось старое количество | количество подгоняется под остаток |
| service worker отдавал старые файлы | после правки кода браузер показывал прежние версии | стратегия «сначала сеть, кеш как запасной вариант», новая версия подхватывается сразу |
| сообщения об ошибках плохо озвучиваются | `role` менялся после появления текста | постоянная живая область `aria-live`, пустая скрыта через `:empty` |
| `aria-label` не совпадал с текстом кнопки | голосовое управление не находило «Назад» | подписи начинаются с видимого текста |
| заполнение базы без транзакции, нет индекса | при сбое мог остаться неполный каталог | заполнение в одной транзакции, индекс на `category_id` |
| мелочи | повтор кода, выбор опций, `scrollIntoView` без учёта `prefers-reduced-motion` | вынесены функции `sendBadRequest`, `createOption`, учтена настройка анимаций |

**Отклонено или оставлено сознательно:**

- *«`app.listen` не передаёт ошибку в колбэк».* Неверно: в Express 5 передаёт. Проверено запуском на занятом порту, сообщение выводится один раз.
- *Нет авторизации у `POST`, `PUT`, `DELETE`.* Для учебной работы без пользователей это вне задания.
- *Корзина не знает об удалении товара в другой вкладке.* Для имитации корзины принято. Подгонка под остаток работает для товаров, которые пришли в текущем ответе сервера.
- *Нет перехода фокуса на поле с ошибкой, нет `aria-invalid`, нет ссылки «К содержимому».* Улучшения доступности сверх требований задания.
- *Константы клиента и сервера дублируются.* Оставлено с комментарием: отдельный эндпоинт для них усложнил бы проект.
- *Сортировка категорий по названию чувствительна к регистру.* Все названия начинаются с заглавной буквы, на текущих данных порядок верный.

## Как проверял

1. `npm test`: 22 теста на временной базе. Они покрывают границы цены, остатка, названия, описания, страницы и лимита, фильтры по цене с включёнными границами, поиск без учёта регистра для русских букв, `%` и `_` в поиске, несуществующие и неверные id, проверку категории, битый JSON, слишком большое тело, XSS-строку. Чтобы убедиться, что тесты не пустые, я трижды ломал код (граница цены, регистр поиска, знак сравнения) и каждый раз тесты падали.
2. В браузере прошёл все сценарии на странице: загрузка, фильтры, пагинация, подробности, корзина с лимитом по остатку, добавление с ошибками формы, правка, удаление с отменой и подтверждением, возврат на предыдущую страницу после удаления, ответ 404 при удалении уже удалённого товара, потеря связи с сервером, тёмная тема и телефонная ширина 375px, быстрые нажатия, двойной клик.
3. Офлайн: после остановки сервера страницы открываются из кеша, каталог показывает «Нет связи с сервером».
4. HTML проверен в [W3C Validator](https://validator.w3.org/nu/): у `shop.html` и `about.html` замечаний нет. У `index.html` остались 4 информационных замечания про `article` без заголовка (карточки из лабораторной 3). CSS проверен в [W3C CSS Validator](https://jigsaw.w3.org/css-validator/): ошибок нет.

Не проверялось: Firefox и Safari, реальный телефон, работа скринридера (доступность проверена по разметке и поведению фокуса, но не озвучкой).
