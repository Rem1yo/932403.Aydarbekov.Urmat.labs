# Лабораторная работа 7. Работа с базой данных (SQLite) и CRUD-операции

Цель: изучить основы работы с реляционными БД, выполнить CRUD-операции и интегрировать их с Express.

Вариант 2: «Товары» (каталог с фильтрацией по цене).

Проект взят из лабораторной 6: к серверу на Express добавлена база данных SQLite и REST-маршруты для товаров. Сайт и `/api/time` работают как раньше.

## Как запустить

```bash
npm install
npm start
```

При первом запуске создаётся файл `shop.db` с таблицей `products` и пятью тестовыми товарами. Файл базы в репозиторий не попадает (он в `.gitignore`). Чтобы начать с чистой базы, достаточно удалить `shop.db` и запустить сервер заново.

## База данных

Таблица `products` создаётся в `db.js`:

| Поле | Тип | Ограничения |
|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT |
| `name` | TEXT | NOT NULL |
| `price` | REAL | NOT NULL |
| `stock` | INTEGER | NOT NULL |

Для работы с SQLite используется пакет `better-sqlite3`.

## Код

- `db.js` - подключение к базе, создание таблицы, тестовые данные, если таблица пустая
- `products.js` - CRUD-функции: `getAllProducts`, `getProductById`, `createProduct`, `updateStock`, `deleteProduct`. Здесь все SQL-запросы
- `server.js` - маршруты Express: проверяют данные запроса, вызывают функции из `products.js` и отправляют ответ

SQL-запросы используют `?` вместо подстановки значений в строку, так значения не могут изменить сам запрос.

## Маршруты

| Метод и адрес | Что делает |
|---|---|
| `GET /api/products` | список товаров |
| `GET /api/products?minPrice=100&maxPrice=500` | товары с ценой от 100 до 500 (`WHERE price BETWEEN`) |
| `POST /api/products` | добавить товар, тело `{ "name": "...", "price": 100, "stock": 5 }` |
| `PATCH /api/products/:id` | изменить остаток, тело `{ "stock": 3 }` |
| `DELETE /api/products/:id` | удалить товар |

Ответ - товар `{ id, name, price, stock }` или массив товаров. Можно указать только `minPrice` или только `maxPrice`.

### Ошибки

| Код | Когда |
|---|---|
| 400 | `name` пустой, `price` не число или меньше 0, `stock` не целое число или меньше 0, `minPrice` и `maxPrice` не числа или отрицательные, в `PATCH` есть поля кроме `stock`, битый JSON |
| 404 | товара с таким `id` нет (в том числе при `PATCH` и `DELETE`) |

`PATCH` меняет только `stock`. Если в теле есть другие поля, сервер отвечает 400 и ничего не меняет.

### Примеры

```bash
curl "localhost:3000/api/products?minPrice=1000&maxPrice=3000"

curl -X POST localhost:3000/api/products \
  -H "Content-Type: application/json" \
  -d '{"name":"Фонарь","price":990.5,"stock":7}'

curl -X PATCH localhost:3000/api/products/1 \
  -H "Content-Type: application/json" \
  -d '{"stock":3}'

curl -X DELETE localhost:3000/api/products/1
```

## Как проверял

Проверял через `curl` на временной базе (переменная `DB_FILE` позволяет указать другой файл, чтобы не трогать `shop.db`).

1. `GET` без параметров вернул 5 товаров. С `minPrice=1000&maxPrice=3000` вернулись 2 товара с ценой 2800 и 1500. Только `minPrice=3000` - 2 товара, только `maxPrice=400` - 1 товар, `minPrice=99999` - пустой массив.
2. Фильтр с `minPrice=abc` и `maxPrice=-5` дал 400.
3. `POST` с корректными данными вернул 201 и товар с новым `id`, пробелы вокруг названия обрезались. Ответ 400 получили: пустое имя, цена -1, остаток -1, цена строкой `"10"`, остаток 1.5, пустое тело и битый JSON. Граничные значения `price: 0` и `stock: 0` принимаются.
4. `PATCH` с `stock: 3` и `stock: 0` сработал, цена и название не изменились. Ответ 400: `stock: -1`, `stock: "5"`, поле `price` вместо `stock`, `stock` вместе с `price`, пустое тело. Для `id` 999 и `abc` ответ 404.
5. `DELETE` существующего товара вернул 200, повторный и с `id` `abc` - 404.
6. После перезапуска сервера данные остались, тестовые товары заново не добавились.
7. Маршруты `/` и `/api/time` из лабораторной 6 по-прежнему отвечают 200.
8. Запустил сервер с настройками по умолчанию: создался файл `shop.db` и 5 тестовых товаров.
