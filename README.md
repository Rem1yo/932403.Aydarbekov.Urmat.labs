# Лабораторная работа 6. Введение в Node.js и базовый сервер на Express

Цель: освоить запуск Node.js-приложений, работу с модулями, создание простого HTTP-сервера, а также превращение статического сайта в PWA (устанавливаемое приложение с офлайн-режимом).

Вариант 2: «Часы и часовые пояса» (API времени).

Сайт из лабораторной 5 теперь отдаётся сервером на Express. Файлы сайта лежат в папке `public`.

## Как запустить

Нужен Node.js. Из папки проекта:

```bash
npm install
npm start
```

В консоли появится `Server started on port 3000`, сайт откроется по адресу http://localhost:3000. Если порт 3000 занят, можно запустить на другом: `PORT=3456 npm start`.

## Маршруты

| Маршрут | Что отдаёт |
|---|---|
| `GET /` | главная страница (`public/index.html`) |
| `GET /about` | страница «Обо мне» (`public/about.html`) |
| `GET /api/time` | время сервера в формате JSON |
| остальные файлы | статика из папки `public` (стили, скрипты, картинки) |
| всё остальное | 404 с текстом «Страница не найдена» |

### /api/time

Query-параметр `format`: если он равен `12`, время приходит в 12-часовом формате с AM/PM, во всех остальных случаях в 24-часовом (по умолчанию). Часовой пояс сервер берёт через `Intl.DateTimeFormat().resolvedOptions().timeZone`.

```
GET /api/time
{ "time": "08:51:16", "timezone": "Asia/Tomsk", "format": "24h" }

GET /api/time?format=12
{ "time": "08:51:16 AM", "timezone": "Asia/Tomsk", "format": "12h" }
```

Если при получении времени произошёл сбой, сервер отвечает кодом 500 и `{ "error": "Internal server error" }`. Если порт уже занят, в консоль выводится понятное сообщение, а не длинная ошибка Node.js.

## Сайт и сервер

На главной странице добавлен блок «Время на сервере»: он раз в секунду запрашивает `/api/time` через `fetch` и показывает время и часовой пояс. Кнопка переключает формат 24/12 часов. Если сервер не отвечает, вместо времени показывается сообщение об ошибке.

## PWA

- `public/manifest.json` - название, цвета, иконки 192x192 и 512x512 (`public/images/icon-*.png`), режим `standalone`. Подключён в `head` обеих страниц.
- `public/sw.js` - service worker. При установке кладёт в кеш страницы, стили, скрипты и иконки. Дальше отвечает из кеша, а если файла там нет, идёт в сеть. Запросы к `/api/` в кеш не попадают, потому что время из кеша было бы неправильным. При смене версии кеша (`CACHE_NAME`) старые кеши удаляются.
- `public/sw-register.js` - регистрирует service worker, подключён на обеих страницах.

Так как service worker кеширует файлы, после правки стилей или скриптов нужно поменять версию в `CACHE_NAME`, иначе браузер покажет старые.

## Как проверял

1. Запустил сервер, запросил маршруты через `curl`: `/`, `/about`, `/api/time`, `/api/time?format=12`, `/api/time?format=24`, `/api/time?format=abc`, `/manifest.json`, `/sw.js`, иконку, стили. Все ответили 200, неизвестные адреса дали 404. Время в ответе совпало с системным (Asia/Tomsk).
2. Проверил порт: запустил второй сервер на занятом порту, получил одно сообщение об ошибке.
3. Проверил ответ 500: запустил сервер с подменой `Intl.DateTimeFormat`, которая выбрасывает ошибку, получил `{"error":"Internal server error"}` и код 500.
4. Открыл сайт в браузере: service worker перешёл в состояние `activated`, в кеше лежат 9 файлов, манифест подключён, иконка отдаётся.
5. Остановил сервер и перезагрузил страницы: `/` и `/about` открылись из кеша со стилями и аватаром, навыки на месте, вместо времени появилось сообщение «Не удалось получить время».

HTML проверен в [W3C Validator](https://validator.w3.org/nu/): ошибок и предупреждений нет, остались 4 информационных замечания про `article` без заголовка (карточки из лабораторной 3). CSS проверен в [W3C CSS Validator](https://jigsaw.w3.org/css-validator/): ошибок нет.
